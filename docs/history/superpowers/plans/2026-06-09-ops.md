# Ops (Sub-project 7 — final) Implementation Plan

> REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Config/infra-heavy. Verify via `docker compose config`, image builds, `golangci-lint`/`actionlint` where available, and `go build`.

**Goal:** Make the boilerplate runnable and shippable: per-service container images, a full local `docker compose` stack (all infra + the 4 services), GitHub Actions CI, a Taskfile covering the dev loop, `.env.example`, and documentation (README, ARCHITECTURE, how-to-add-a-service).

**Architecture:** Multi-stage distroless images per service. Compose brings up Postgres (+PgBouncer), Redpanda (Kafka API + Schema Registry + Console), Redis, MinIO, Keycloak, and the observability stack (OTel Collector → Jaeger + Prometheus + Grafana + Pyroscope), then the 4 services wired to them via env. CI runs lint + buf + tests (Docker-on-runner for testcontainers) + image builds.

---

## Task 1 — Dockerfiles + docker-compose full stack + Taskfile + .env.example
- `Dockerfile` (one parametric, or `deploy/docker/<svc>.Dockerfile`): multi-stage — `golang:1.25` builder (`CGO_ENABLED=0 go build -o /bin/<svc> ./examples/<svc>/cmd/<svc>`) → `gcr.io/distroless/static:nonroot` runtime. A build ARG `SERVICE` selects which cmd to build (single Dockerfile, `--build-arg SERVICE=orders`). Non-root, no shell.
- `docker-compose.yml` at repo root:
  - **infra**: `postgres:16-alpine` (one instance; init script creates 4 DBs: gateway, orders, payments, notifications), `pgbouncer` (edoburu/pgbouncer or bitnami) in transaction mode pointing at postgres (document the prepared-stmt note), `redpandadata/redpanda` (Kafka + Schema Registry) + `redpandadata/console`, `redis:7-alpine`, `minio/minio` (+ a `createbuckets` one-shot), `quay.io/keycloak/keycloak` (dev mode, import a realm with a client + roles), `otel/opentelemetry-collector`, `jaegertracing/all-in-one`, `prom/prometheus` (+ `deploy/prometheus.yml`), `grafana/grafana`, `grafana/pyroscope`.
  - **services**: gateway (ports published), orders, payments, notifications — each `build: {context:., dockerfile:Dockerfile, args:{SERVICE:<svc>}}`, env wired to the infra hostnames (PG_DSN, KAFKA_BROKERS=redpanda:9092, REDIS_ADDRS, S3_ENDPOINT=minio:9000, OTEL_EXPORTER_OTLP_ENDPOINT=otel-collector:4317, GATEWAY_JWKS_URL=keycloak realm certs, etc.), `depends_on` with healthchecks. A `migrate` profile/one-shot per service is optional — services run their own Migrate on startup (they already do).
  - healthchecks for postgres/redpanda/minio/keycloak so services wait.
- `deploy/`: `prometheus.yml` (scrape services /metrics — note: metrics endpoint is a documented gap until wired; scrape what exists), `otel-collector.yaml` (receive OTLP, export to Jaeger + Prometheus), `keycloak/realm-export.json` (realm `app`, client `gateway`, roles admin/user, a test user), `postgres/init.sql` (CREATE DATABASE gateway/orders/payments/notifications), `grafana/` provisioning (datasources: prometheus, jaeger, pyroscope) — keep minimal but valid.
- `.env.example` documenting every env var the services read (PG_*, KAFKA_*, REDIS_*, S3_*, OTEL_*, GATEWAY_*, OUTBOX_*, etc.) with sane local defaults.
- Update `Taskfile.yml`: `up`/`down` (compose), `logs`, `migrate` (optional), `buf` (lint+generate), `sqlc` (generate all), `lint`, `test`, `test-short` (skip container tests via `-short` if services honor it — optional), `build-images`.
- VERIFY: `docker compose config` validates (no run needed); build ONE service image (`docker build --build-arg SERVICE=gateway -t gw:test .`) succeeds; `task` lists tasks. Do NOT need to bring the whole stack up (slow) — but if quick, `docker compose up -d postgres redpanda` smoke is a bonus.
- Commit `feat(ops): Dockerfiles, full docker-compose stack, deploy configs, Taskfile, .env.example`.

## Task 2 — GitHub Actions CI + documentation
- `.github/workflows/ci.yml`:
  - jobs: **lint** (setup-go 1.25, golangci-lint-action v6 with the repo's v2 config), **buf** (bufbuild/buf-setup + buf lint + buf breaking against main), **test** (Docker available on ubuntu-latest runners → testcontainers work; `go test -race ./...` — note this is slow with containers; optionally split unit vs integration, but keep it correct), **build** (build all 4 images via the parametric Dockerfile in a matrix). Cache go modules. Trigger on push + PR.
  - `actionlint` the workflow if available; otherwise ensure valid YAML.
- Docs:
  - `README.md` (repo root): what this is, the stack table, architecture diagram (ascii/mermaid of the choreography), quickstart (`task up`, hit the gateway, observe in Jaeger/Grafana), how to run tests (Docker required), project layout (platform vs examples), "delete examples/ + proto for a clean starter."

  - `docs/adr/` (a few short ADRs): caarlos0/env over cleanenv; typed-decorators over go-mediatr; manual DI over fx; outbox+inbox effectively-once; franz-go.
- Final whole-repo verification: `go build ./...`, `go vet`, `gofmt -l`, `golangci-lint run`, and a NOTE that `go test -race ./...` requires Docker. Confirm the platform/examples boundary once more.
- Commit `docs(ops): CI workflow, README, ARCHITECTURE, adding-a-service guide, ADRs`.
